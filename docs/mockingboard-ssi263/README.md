# Mockingboard SSI-263 speech expansion — separate A2N20V2-Enhanced workstream

## Scope and honest status (2026-11-06)

This is an **independent experimental branch**, based on the corrected native-AY/BL616-HID branch
`petar/mcu-timeout-hid-upstream-20261106`, **NOT** on the MB-to-DOC P3/SynthLAB piano
experiments. Those musical experiments are preserved.

**P0 contains a tested SSI-263 Apple II register bus front-end, not audible speech.**
No SSI phoneme ROM, formant DSP, audio sample pipeline, full hardware protocol, or speech
output is connected to the Enhanced top-level in this revision. Do **not** build or flash
this branch expecting speech. The initial purpose is to establish a safe bus contract and
portability requirements before adding a complex third-party core.

The likely source project is [Appletini One](https://github.com/hasseily/appletini-one),
which implements a *native SSI-263* FPGA speech engine, not just Mockingboard music.
If a different SSI repository was intended, verify its URL before importing anything.

## Hardware target

- Apple IIe with A2N20V2-Enhanced, Tang Nano 20K (Gowin GW2AR-18C).
- Standard Mockingboard/Phasor has two VIAs and two 3-channel AY generators.
- Proposed SSI-263AP Model C socket overlays $Cn40–$Cn7F, with A2:A0 selecting
  the SSI register; $Cn80–$CnFF remain the other VIA.
- SSI audio must be mixed with the native 6-channel AY stereo, not replace it.
- SSI A/R feeds VIA CA1. The bus's D7 status is generated by the speech core,
  not by a constant fake-ready value.
- Future socket-2/Phasor mapping will be a separate, tested feature.

The standalone `ssi263_slot_frontend` currently implements:
1. Qualified $Cn40-$Cn7F selection and 8 mirrored 3-bit SSI register addresses.
2. One write pulse per Apple bus high phase; no repeats for a held write.
3. A read selection and the speech engine's status bit on D7.
4. Transparent SSI A/R -> VIA CA1, retaining high idle when disabled.
5. Preservation of unrelated VIA accesses and disabled configurations.

The front-end has not been connected to `hdl/mockingboard/mockingboard.sv`, because
a present-but-silent SSI device must never be advertised to Apple II software as
a working speech chip. We will integrate the front-end with a real controller and
PCM engine together, behind a disabled-by-default synthesis parameter.

## Most important porting constraint: clocks

Appletini's native engine is validated on a **133.333 MHz** Xilinx Zynq design.
Its documented peak completion latency is **121 fabric clocks** from an effective
SSI XCK event to tick_done; the clock period between effective XCK events is
approximately 0.98 us. The A2FPGA Enhanced native fabric typically runs at
**54 MHz**, yielding only ~53 clocks per SSI event — much too few for the
unchanged Appletini pipeline. Simply adding source files to Gowin will NOT
implement working speech.

Possible paths:
- Clock the imported speech engine in an appropriate independent ~133–162 MHz
  domain, using proper input event CDC and 44.1 kHz PCM crossing; investigate
  GW2AR PLL, timing, DSP and logic resource headroom.
- Or retime/rearchitect the native five-formant pipeline for the available
  fabric clock. Preserve phoneme/SSI clock timing; do **not** slow down XCK to
  disguise missed deadlines.

Appletini PCM uses a 48 kHz sample stream; Enhanced HDMI outputs 44.1 kHz.
The speech mixer requires a deliberate sample-rate interface and saturating
mix, and the native AY path must remain unchanged with SSI disabled.

## Resource feasibility

Appletini documents isolated Xilinx estimates of **3467 LUT / 2112 FF /
12 DSP** for its native speech engine, and a much larger whole-system
utilization. This is not a Gowin resource report. Determine whether one socket
fits next to the existing DOC, SDRAM, VIA, AY, HDMI and MCU logic before
attempting two independent SSI sockets.

## Suggested next milestones

1. Baseline: run the independent SSI bus CI; confirm no native AY/MCU changes.
2. Import Appletini's GPL-compatible SSI-263 modules into a dedicated third-party
   folder with original headers and attribution, plus its 512-byte parameter ROM,
   for **standalone simulation only**.
3. Run its phoneme clocking tests at actual 54 MHz vs a candidate separate PLL
   clock; reject silent/overrun results. Obtain Gowin synthesis resource numbers.
4. Hook real SSI D7/CA1 and register writes into the existing Mockingboard
   instance only when the speech engine passes internal checks. Keep opt-in OFF
   by default.
5. Add 48-to-44.1 kHz PCM, stereo mixer headroom, and physical Apple IIe
   speech software tests. Preserve the native AY mix and P3 music branch.

## Test and build

Run standalone bus simulation in any shell with Icarus:

```sh
iverilog -g2012 -s tb_ssi263_slot_frontend -o /tmp/ssi263-bus.vvp hdl/mockingboard/ssi263_slot_frontend.sv tests/ssi263/tb_ssi263_slot_frontend.sv
vvp /tmp/ssi263-bus.vvp
```

GitHub Actions workflow: `.github/workflows/ssi263-bus.yml`.

**DO NOT flash an FPGA image from this P0 branch for SSI audio.** Nothing in
this P0 branch claims full SSI-263 synthesis or physical speech output.
