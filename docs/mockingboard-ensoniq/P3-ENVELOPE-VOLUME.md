# P3 — Real YM envelope level, PSG reset/mute, and -2 dBFS MB-DOC output

**Branch:** `petar/mb-doc-p3-envelope-gain`  
**Base:** `petar/mockingboard-ensoniq-p0` (preserved as the hardware-proven P2 first-musical-playback baseline)  
**Validation:** Icarus bridge/capture RTL suite passed in GitHub Actions [run 42302358360](https://github.com/ppuskari/a2fpga_core/actions/runs/42302358360). **Gowin synthesis, timing, and physical Apple IIe playback have NOT yet been validated for P3.**

## Motivation and measurements

The original three-selection Apple IIe Mockingboard recording (`MockingboardTest1.wav`, 44.1 kHz stereo, 16-bit PCM) had an absolute maximum of **4,503 counts / 32,768 = -17.24 dBFS**. Its long sustained chords and absent noise explosion showed that P2 was making real polyphonic DOC music but lacked AY envelope-controlled note-off and noise synthesis.

P2 has the following deliberate limitation: AY amplitude bit 4 uses a **permanent full-level preview** rather than the envelope waveform generated by AY registers 11–13. This can make a tune's expected decay become a held tone. Another way for a player to stop is to assert the actual AY/YM reset through Mockingboard VIA port B bit 2, which the old bridge did not mirror.

## P3 envelope implementation

**We reuse the existing native YM2149 generator**; we do **not** build a second unsynchronized envelope implementation.

- `hdl/support/YM2149.sv` now exports `ENV_LEVEL[4:0]`, exposing its internally clocked 32-step `env_vol`. The core itself already implements AY/YM envelope **period registers 11 and 12**, **shape/retrigger register 13**, and the 32-level step sequence. Clock-divider and envelope-period counters are initialized deterministically on PSG RESET; register-13 retrigger also restarts its envelope-period counter. The existing native waveform and output channels are otherwise untouched.
- `hdl/mockingboard/mockingboard.sv` routes the *independent* left/right native envelope levels and VIA PB2 PSG reset status outward to the bridge.
- `boards/a2n20v2-Enhanced/hdl/mb_doc_bridge.sv` uses the live YM envelope level whenever channel amplitude register **8/9/10 bit 4** is set. Fixed 4-bit amplitude maps through the same 32-step logarithmic approximation. The maximum per-voice DOC volume remains **208**, as in P2, to avoid changing DOC internal mix headroom.
- The per-chip VIA PB2 reset clears that chip's captured AY shadow register bank. A reset during or after a song can no longer leave the old captured amplitudes live indefinitely.
- The DOC bridge updates six independent oscillator volume and control registers on its existing scan schedule; it does **not** unnecessarily halt and retrigger every pitch update.

### Envelope fidelity boundary

This implementation follows the **currently integrated YM2149 HDL core's** interpretation of AY envelope shapes; it is not an independently validated analog AY-3-8913 timing model. Tests of register-13 shape codes 0–15 against native audio and real hardware remain appropriate. Noise register 6 and mixer noise bits (7[5:3]) are **still not implemented** in the DOC bridge; the missing explosion will probably remain absent until the noise phase.

## P3 HDMI output gain (MB-DOC only)

The earlier Enhanced HDMI post-filter function multiplied the raw PCM by **45/32 = 1.40625** (approximately +2.96 dB). P3 keeps that function **unchanged for native/GS mode**. For `AUDIO_MODE_MB_DOC=1`, the new path:

1. Multiplies the signed 16-bit post-filter PCM by **8**, using a width-safe shift.
2. Saturates to **±26,028 signed PCM counts**, approximately **-2.00 dBFS peak**.
3. Reports any limiting to the existing HDMI clipping-history telemetry.

Relative to the old `45/32` multiplier, the extra factor is **8 / 1.40625 = 5.6889× (+15.10 dB)**. On the recorded test, the predicted original peak becomes approximately **-2.14 dBFS** (below the ceiling). Other recordings can be louder; the limiter prevents full-scale integer wraparound but repeated saturation **can distort** the sound. If the HTML debug clip history shows frequent clipping or the audio is harsh, reduce the gain in a subsequent controlled build rather than increasing the source oscillator volumes.

The P3 HDMI gain cannot affect normal GS/OS DOC or IIgs Sound GLU mode because `AUDIO_MODE_MB_DOC` is a synthesis-time constant.

## Regression tests

The existing `tests/mb_doc/run_capture_test.sh` runs two Icarus test benches:

- AY capture transaction boundaries, both chips, and repeated writes to AY register 13.
- DOC initialization of 256 waveform bytes, independent stereo voices, pitch conversion, zero-volume mute, and retrigger-free updates.
- **New in P3:** envelope level 31 → full volume, envelope level 0 → volume zero and HALT, fixed-volume recovery, and VIA-PB2 reset clearing the captured register bank so a stopped note cannot resume.

Run `sh tests/mb_doc/run_capture_test.sh` with `iverilog` and `vvp` installed. The CI workflow also includes `petar/mb-doc-p3-envelope-gain`.

The standalone bridge bench injects envelope **levels**; its PASS does not independently test the native `YM2149.sv` envelope timing/shape logic or the complete Gowin top-level synthesis. These need the FPGA compile and hardware A/B test.

## Safe Apple IIe hardware deployment

1. Preserve the currently working P2 `.fs` bitstream and keep a copy of the three-song WAV for comparison.
2. Clone or fetch this branch into a **new directory** so the P2 checkout is not overwritten.
3. Open `boards/a2n20v2-Enhanced/a2n20v2_enhanced.gprj` in Gowin. **IMPORTANT:** Build with `AUDIO_MODE_MB_DOC=1` as a top-level synthesis parameter or define `MB_DOC_EXPERIMENT`; the unchecked default is normal mode `AUDIO_MODE_MB_DOC=0` and will *not* test the bridge.
4. Synthesize and place/route, inspect resource/timing reports, and preserve the result under a P3-specific filename before programming it.
5. Use the **separately corrected USB HID + timeout BL616 Stage 2** firmware (branch `petar/mcu-timeout-hid-upstream-20261106`). No change to BL616 Stage 1 is necessary for this FPGA test.
6. Keep the Apple IIe Enhanced virtual slots set to **only Mockingboard in slot 4**, as in the successful P2 experiment.
7. Run the same three musical selections. Confirm dynamics, envelope decay, manual stop, and the eventual return to silence. Verify both left/right voices. Observe the HDMI clipping-history indicator if available.
8. Run a noise-heavy explosion last; do **not** interpret its continued absence as a P3 regression, because noise synthesis is still future work.
9. If the FPGA fails to start, sound is wrong, or clipping is excessive, return immediately to the saved P2 `.fs` and compare.

### Success criteria for P3

- A recognizable six-voice stereo melody, with substantially stronger HDMI output **without persistent peak clipping**.
- Envelope-controlled notes rise/decay/hold instead of behaving as permanently fixed level 15.
- An AY/VIA reset silences both corresponding DOC voices and prevents old pitch/volume values from reappearing.
- No hardware regression in slot 4 Mockingboard identification or IIe video.

**Not included:** AY noise generator and full noise/tone conjunction, general per-instrument wavetable selection, or concurrent GS/DOC and MB ownership. Those are following phases.
